# Linux Security Audit with Lynis — Hardening Score and Remediation

> ⚠️ **Context**: audit performed exclusively on my personal Kali Linux VM (isolated lab on UTM, private home network). No third-party systems were touched. All applied fixes are reversible and documented.

## 📌 Objective

Run a real security audit on a Linux VM with [Lynis](https://cisofy.com/lynis/) (the same kind of tool used professionally to check compliance against baselines such as the CIS Benchmarks), identify concrete weaknesses, apply targeted fixes, and measure the improvement with a before/after comparison based on the Hardening Index.

## 🧩 Context / Scenario

Personal lab (see [home-lab-cybersecurity](https://github.com/luigiderosa2299-gif/home-lab-cybersecurity)): Kali Linux VM on UTM, private home network — the same VM used in the [ssh-brute-force-detection-lab](https://github.com/luigiderosa2299-gif/ssh-brute-force-detection-lab) project.

## 🛠 Technologies and Tools

- **Lynis 3.1.7** — open-source security auditing tool for Unix/Linux systems, used for compliance and hardening assessment
- **fail2ban** — intrusion prevention, automatically bans hosts after repeated authentication failures
- **libpam-passwdqc** — PAM module for checking password strength
- Environment: Kali Linux (Kali GNU/Linux Rolling 2026.3) on UTM

## ⚙️ What I Did

### 1. Baseline — Initial Audit

```bash
sudo lynis audit system
```

**Baseline result**: see [`docs/baseline-report.md`](docs/baseline-report.md)
- **Hardening Index: 65/100**
- 277 tests performed, 47 suggestions, 0 critical warnings
- Software components: Firewall ✅, Intrusion software ❌, Malware scanner ❌

### 2. Analysis of the Suggestions

I reviewed the full list of the 47 suggestions generated by Lynis (saved in `/var/log/lynis-report.dat`) and selected 3 concrete, low-risk fixes, prioritized by real impact on the security posture:

| Lynis ID | Suggestion | Priority |
|---|---|---|
| DEB-0880 | Install fail2ban to automatically ban hosts with repeated authentication failures | High — directly tied to the brute force detection in the [ssh-brute-force-detection-lab](https://github.com/luigiderosa2299-gif/ssh-brute-force-detection-lab) project |
| AUTH-9262 | Install a PAM module for password strength checking | Medium |
| AUTH-9286 | Configure minimum/maximum password age in `/etc/login.defs` | Medium |

### 3. Applying the Fixes

**Fix 1 — fail2ban**:
```bash
sudo apt install -y fail2ban
sudo systemctl enable --now fail2ban
```

**Fix 2 — password strength checking**:
```bash
sudo apt install -y libpam-passwdqc
```

**Fix 3 — password expiry** in `/etc/login.defs`:
```
PASS_MAX_DAYS   90
PASS_MIN_DAYS   1
```

### 4. Re-scan and Comparison

```bash
sudo lynis audit system
```

**Final result**: see [`docs/final-report.md`](docs/final-report.md)
- **Hardening Index: 68/100** (+3 punti)
- 278 tests performed, 43 suggestions (-4 compared to the baseline)
- Software components: Firewall ✅, **Intrusion software ✅** (fail2ban detected as active), Malware scanner ❌

## 📊 Before/After Comparison

| Metric | Baseline | After fixes | Delta |
|---|---|---|---|
| Hardening Index | 65/100 | 68/100 | **+3** |
| Open suggestions | 47 | 43 | **-4** |
| Intrusion software | ❌ Absent | ✅ Active (fail2ban) | Resolved |

## 🧱 Observations

A 3-point increase on an already reasonably well-maintained system (Kali Linux starts from a more hardened base than a generic desktop distribution) confirms an important security hardening principle: **marginal improvements require increasing effort** — the first fixes (the high-impact ones, such as intrusion prevention) are relatively quick to apply, while reaching a much higher score would require more invasive changes (separate disk partitions for `/home` and `/var`, GRUB password hardening, disabling USB/firewire drivers) that need to be weighed carefully against the usability of the system in an active lab context.

The remaining 43 suggestions include changes with a greater impact on the VM's day-to-day usability (e.g. disabling USB storage) that were not applied in this iteration so as not to compromise lab operations.
